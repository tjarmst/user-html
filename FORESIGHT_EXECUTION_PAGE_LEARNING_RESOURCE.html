Foresight Execution Page Learning Resource

This guide teaches users how the **Foresight Execution** page connects scenarios, signals, watchpoints, alerts, and mitigation tracking.

Purpose

Foresight Execution turns scenario monitoring into execution-aware governance review.

Use it to:

  • inspect seeded or configured scenarios
  • review scenario-to-execution effectiveness
  • inspect scenario execution review context
  • maintain the signal register
  • record signal direction and watchpoint status
  • review alert detail
  • update mitigation status, owner, due date, and notes

Scenario monitoring is only useful when it connects to mitigation and execution evidence.

Signal Register

Signals record observed scenario movement.

Key fields include:

  • linked scenario
  • signal direction
  • watchpoint status
  • note

Watchpoint statuses include watch, triggered, critical, and cleared.

Alerts And Mitigation

Alerts surface watchpoint-triggered governance pressure.

Mitigation tracking records:

  • mitigation status
  • owner
  • due date
  • mitigation note

Mitigation statuses include unplanned, planned, in progress, mitigated, and accepted.

Review Context

The page can display scenario execution review context with semantic and handling meaning. Use it to distinguish supported mitigation from weak, incomplete, or blocked claims.

Downstream Impact

Foresight Execution feeds:

  • Recommendations trigger basis
  • Preserve / Reform / Replace scenario escalation
  • Governance Summary watchpoint alerts and gates
  • Governance Execution Review
  • Scenario Effectiveness Review
  • Lineage View scenario overlay

Common Mistakes

Avoid treating a watchpoint as mitigated because it was acknowledged.

Avoid treating default seeded technology watchpoint context as strong proof by itself.

Avoid recording mitigation without an owner when action is expected.

Avoid ignoring critical alerts when accepting decisions.

Training Prompt

Ask the trainee to save a scenario signal, inspect the resulting alert, update mitigation tracking, and explain whether the alert should block, caution, or simply monitor governance action.

Completion standard: the user can connect scenario pressure to accountable mitigation review.
