Diagnostic Input Page Learning Resource

This guide teaches users how the Diagnostic Input page captures structured observations for the current assessment cycle.

Purpose

Diagnostic Input records observed metric values for the selected organization and assessment cycle.

Use it to:

  • enter Stage A structural, symbolic, alignment, technology, and readiness observations
  • review metric definitions and scoring cues
  • compare against prior observed values when available
  • save metric observations for scorecard computation
  • export or print saved diagnostic metric observations for the current cycle, division, and segment

The page is about disciplined Stage A input, not interpretation by itself.

Stage A Metric Role

Diagnostic Input is mainly Stage A: Understand reality. It records evidence-backed observations about current workplace conditions before the system recommends, decides, pilots, or reviews action.

Some inputs also indicate readiness for Stage B. For example, PILOT_CAPACITY, DATA_QUALITY_SCORE, STAKEHOLDER_SUPPORT_AVG, LEARNING_CULTURE, and LEADERSHIP_SUPPORT still describe current reality, but they also tell governance whether intelligent change can proceed responsibly.

Metric Definitions

Each metric has:

  • code
  • name
  • domain
  • description
  • polarity
  • value range

Polarity matters. For some metrics, higher values are healthier. For others, lower values indicate healthier conditions.

If metric definitions are missing in a real organization workflow, go to Home and use Initialize framework definitions. Do not use Load sample data unless the user intentionally wants the separate sample workspace.

Workflow

The user should:

  1. Confirm organization and cycle context.
  2. Confirm the selected organization is the intended real or sample workspace.
  3. Read the metric definitions and scoring cues.
  4. Enter values for the assessment window.
  5. Use notes where interpretation needs context.
  6. Review observations before saving.
  7. Persist metric observations.

The page supports review before save so users can catch default or accidental entries.

The progress message treats any value of 50 as a possible default or placeholder, even if that value was previously saved. A saved value of 50 may still be legitimate, but the user should be able to explain why it is neutral rather than accidental.

Export And Print

The Export / print saved diagnostic input expander lets the user save a local copy of saved metric observations.

Available outputs:

  • Diagnostic input CSV
  • Printable diagnostic input HTML

Exports include persisted records for the currently selected cycle, division, and segment. If the user has just edited values in the form, they should save first before exporting. Unsaved form edits are not included.

What The User Should Notice

Ask the user to identify:

  • current organization and cycle
  • whether the current organization is sample data or user data
  • metric domain groups
  • higher-is-healthier or lower-is-healthier cues
  • non-default entries
  • prior observed values
  • review progress before saving
  • whether any value of 50 is intentional evidence or only a placeholder
  • whether the export scope matches the intended cycle, division, and segment

Downstream Impact

Diagnostic Input feeds:

  • Score Dashboard scorecard computation
  • Alignment Dashboard gap analysis
  • Score Component Details
  • Recommendations generation
  • Governance Summary
  • Comparative Cycle Review
  • local CSV or printable HTML records of saved numeric inputs

It does not itself prove improvement. Improvement is tested later through Stage B signals such as pilot outcomes, KPI progress, execution feedback, learning state, and governance action resolution.

Common Mistakes

Avoid treating default values as real observations.

Avoid exporting before saving recent edits.

Avoid mixing time periods inside one cycle.

Avoid entering values without reading polarity.

Avoid using diagnostic input as evidence narrative. Use Evidence Notes for source, confidence, and interpretation.

Training Prompt

Ask the trainee to enter a small set of metric observations, explain polarity for two metrics, review the entries, save them, and download the diagnostic CSV or printable HTML.

Completion standard: the user can explain how a saved metric observation becomes part of scorecard computation and how to export the saved input record.
