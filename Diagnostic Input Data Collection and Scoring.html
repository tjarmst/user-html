Diagnostic Input Data Collection And Scoring

Purpose

Diagnostic Input is mainly a Stage A: Understand reality activity. It records evidence-backed observations about current workplace conditions so the system can compute scorecards, expose contradictions, and support recommendations.

The goal is not to produce optimistic scores. The goal is to create a defensible picture of current reality that can later be challenged, acted on, and retested.

How Diagnostic Input Fits The Product

Some Diagnostic Input metrics also indicate readiness for Stage B. PILOT_CAPACITY, DATA_QUALITY_SCORE, STAKEHOLDER_SUPPORT_AVG, LEARNING_CULTURE, LEADERSHIP_SUPPORT, and ROLE_REDESIGN_RATE help determine whether the organization can act and learn responsibly.

Diagnostic Input Elements

Diagnostic inputs can include:

  • objective operational data, such as overtime, leave, role redesign, or technology deployment evidence;
  • perceptual survey or interview responses, such as dignity, psychological safety, leadership support, or technology experience;
  • composite or derived indicators, such as burnout risk, trust health, or data quality;
  • structured judgment converted to a 0-100 scale using a documented rubric.

Stage B execution evidence, such as pilot outcome scores and KPI progress, should be handled as execution feedback rather than as a substitute for Stage A diagnosis.

Collection Process

1. Clarify the metric role

Before collecting data, identify whether the metric is:

  • a Stage A diagnostic metric;
  • a Stage A / Stage B readiness metric;
  • a Bridge / governance metric such as an alignment gap.

This helps the collector understand whether the metric describes current reality, readiness to act, or the quality of interpretation.

2. Clarify polarity

Determine whether higher values are healthier or riskier.

Positive examples:

  • SUSTAINABLE_WORKLOAD_SCORE
  • DIGNITY_AT_WORK
  • PSYCHOLOGICAL_SAFETY
  • AI_AUGMENTATION_RATIO

Negative examples:

  • OVERTIME_HOURS_NORM
  • STRESS_LEAVE_RATE
  • POLITICAL_REWARD_BIAS
  • SURVEILLANCE_DRIFT_SCORE
  • SYMBOLIC_STRUCTURAL_INTEGRITY_GAP

3. Identify the strongest evidence source

Use the strongest available source for each metric:

  • operational systems: HRIS, payroll, timekeeping, rostering, workforce planning, people analytics;
  • surveys: employee climate surveys, pulse surveys, leadership assessments;
  • interviews and focus groups: structured conversations with employees, managers, and stakeholders;
  • document review: policies, advancement criteria, technology governance material, incident records;
  • program data: pilot reports, KPI reports, deployment evidence, project retrospectives.

4. Keep assessment boundaries consistent

Use the same assessment window, organization, division, and workforce segment definitions for the metrics in a cycle. If a metric only applies to a subset, record that limitation in the note or evidence record.

5. Record confidence and rationale

Every metric should have enough context for a reviewer to understand why the value was entered:

  • source;
  • period covered;
  • confidence level;
  • calculation or rubric;
  • known limitations;
  • reason for using a placeholder, if one is used.

Scoring Methods

Objective operational metrics

Use this method for counts, rates, ratios, or direct operational data.

  1. Define the raw measure.
  2. Extract data for the assessment window.
  3. Normalize to the 0-100 scale.
  4. Confirm whether lower or higher is healthier.
  5. Record source details and caveats.

Examples:

  • OVERTIME_HOURS_NORM
  • STRESS_LEAVE_RATE
  • ROLE_REDESIGN_RATE

Perceptual survey metrics

Use this method for employee or stakeholder perception.

  1. Align survey questions to the metric definition.
  2. Use a consistent response scale.
  3. Convert the average to the 0-100 scale.
  4. Review sample size and segment coverage.
  5. Record limitations and confidence.

Example conversion:

1-5 Likert average -> ((average - 1) / 4) * 100

Examples:

  • DIGNITY_AT_WORK
  • PSYCHOLOGICAL_SAFETY
  • LEADERSHIP_SUPPORT
  • AI_USE_TRANSPARENCY

Composite or derived metrics

Use this method when the metric represents a combined condition.

  1. Identify the component measures.
  2. Define the weighting or aggregation rule.
  3. Calculate the score.
  4. Validate the result against the intended meaning.
  5. Record enough detail for review.

Examples:

  • BURNOUT_RISK_SCORE
  • TRUST_HEALTH_SCORE
  • DATA_QUALITY_SCORE

Structured judgment metrics

Use this method when objective data is incomplete but a decision still requires disciplined assessment.

  1. Assemble evidence.
  2. Use a rubric.
  3. Score criteria consistently.
  4. Review with a multidisciplinary group where appropriate.
  5. Record the final value and the reasoned basis.

Examples:

  • POLITICAL_REWARD_BIAS
  • HIDDEN_EXIT_PRESSURE
  • CAPABILITY_RECOGNITION
  • WORKER_VOICE_IN_TECH

Handling Contradictions

When objective data and perceptual evidence differ materially, do not smooth the difference away. Treat the difference as a governance signal.

Examples:

  • Overtime is high, but workload is reported as sustainable.
  • Leadership says technology augments workers, but survey evidence reports surveillance drift.
  • Promotion criteria are documented, but employees experience advancement as political.

Contradictions should be linked to evidence and reviewed in Score Component Details or later governance review pages.

Using Neutral Placeholders

Use 50 only when evidence is not yet available or is genuinely neutral. Label it as interim. A placeholder should create a plan for better evidence, not become a permanent convenience.

Avoid using 50 to hide uncertainty. The product creates value by making weak evidence visible.

Evidence Traceability

Metric values should not stand alone. Use Evidence Notes and Score Component Details to preserve the reason behind the score.

Good evidence records should clarify:

  • what was observed;
  • who or what was affected;
  • whether the evidence is mechanism, interpretation, contradiction, or validation;
  • confidence level;
  • link to the relevant score group, score component, recommendation, decision, pilot, KPI, or governance path where appropriate.

Review And Iteration

At the end of each assessment cycle:

  1. Review low or high-impact metrics for evidence sufficiency.
  2. Review contradictions before relying on recommendations.
  3. Compare current-cycle scores with prior cycles where possible.
  4. Revisit placeholder values.
  5. Use Stage B pilot and KPI evidence to test whether action changed the condition.

Owner Summary

Diagnostic Input creates the evidence base for Stage A. Its value is reliability: it gives owners a clearer picture of current workplace conditions before they decide what to preserve, reform, replace, pilot, escalate, or review.
