Assessment Cycle Page Learning Resource

This guide teaches users how the **Assessment Cycle** page works and how cycles support cross-cycle learning.

Purpose

An assessment cycle is a bounded review period, such as a baseline, quarterly review, or follow-up cycle.

Use the page to:

  • create a cycle
  • select the active cycle
  • edit cycle dates, label, and status
  • remove a cycle created in error when it has no attached records
  • prepare a later cycle by carrying forward active recommendation series

Most app records are interpreted through the currently selected cycle.

Cycle Dates Matter

Earlier and later cycles are determined by start and end dates, not by cycle ID or creation order.

This matters for:

  • Comparative Cycle Review
  • predecessor recommendation choices
  • carry-forward workflows
  • continuity correction guards
  • KPI threshold interpretation across cycles

A later-created row can still represent an earlier cycle if its dates are earlier.

Cycle Status

Typical statuses are:

  • `draft`: the cycle exists but is not ready for full review
  • `active`: data entry and workflow are underway
  • `review`: governance review is in progress
  • `closed`: the cycle is treated as complete

Status is a governance cue. It does not automatically prove data completeness.

Prepare Next Cycle

The **Prepare next cycle** workflow carries active recommendation series from an earlier cycle into a later cycle.

Carry-forward creates a separate recommendation record in the target cycle while preserving the series link and predecessor reference.

Use it when:

  • an unresolved series should continue
  • a prior recommendation needs revision in a later cycle
  • continuity should be explicit before new generation or review

Do not use it to duplicate recommendations without governance reason.

What The User Should Notice

Ask the user to identify:

  • selected cycle label
  • start and end dates
  • cycle status
  • earlier and later cycles
  • carry-forward candidates
  • unlinked source-cycle recommendations

Downstream Impact

Assessment Cycle affects:

  • Diagnostic Input and Survey Input records
  • scorecard persistence
  • recommendation generation
  • comparative review
  • continuity predecessor eligibility
  • board-pack exports
  • review history filtering

Training Prompt

Ask the trainee to select a current cycle, identify its previous dated cycle, and explain which recommendation series should be carried forward.

Completion standard: the user can explain cycle order by dates and can distinguish carry-forward from copying text manually.
