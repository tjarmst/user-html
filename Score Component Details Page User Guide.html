Score Component Details Page User Guide

Purpose

The Score Component Details page is the bridge between a computed score and defensible governance interpretation.

It helps users inspect how Stage A diagnostic inputs contributed to the scorecard, link evidence to score components, and record review notes for contradictions or confidence concerns.

In the operating model:

  • Stage A asks: What is really happening?
  • Stage B asks: Is our response working?
  • Score Component Details asks: Can we defend the interpretation of the score before we act on it?

How This Page Creates Value

The page prevents scorecard results from becoming unexplained numbers. It lets users:

  • inspect component values and score groups;
  • see which evidence is already linked;
  • add or relink evidence;
  • review contradictions;
  • add review notes;
  • improve traceability before recommendations, governance summaries, or later review pages rely on the score.

Readiness Requirements

The page requires:

  • selected organization context;
  • selected assessment cycle;
  • a computed and persisted scorecard.

If no scorecard exists, compute one in Score Dashboard first.

Score Groups

Score groups can include ordinary metric-input groups and contradiction groups. Use the selected group to understand what kind of evidence you are reviewing.

Common review questions:

  • Is this a structural input, symbolic input, or alignment signal?
  • Is the value low because the condition is weak, or because the metric is negative and high values are risky?
  • Is the component supported by evidence?
  • Is the component contradicted by survey or qualitative evidence?
  • Does the component affect recommendations or governance posture?

Component Details

Each component can show:

  • component name;
  • raw value;
  • normalized value;
  • weight;
  • source notes;
  • review status;
  • review note;
  • linked evidence.

Use these details to decide whether the score is ready to support interpretation or whether more evidence is needed.

Evidence Roles

When creating or linking evidence, choose the role carefully:

Evidence roleMeaning
MechanismExplains how a structural condition is produced.
InterpretationHelps explain meaning, trust, dignity, legitimacy, or perception.
ContradictionChallenges or complicates the current conclusion.
ValidationSupports or tests a conclusion.

Mechanism evidence is especially important for structural primacy. Interpretation evidence is also valuable, but it should not be used to compensate for severe structural weakness.

Relinking Existing Evidence

Use evidence relinking when an existing note better belongs with a score component than where it was first attached. This preserves the evidence trail and avoids duplicate notes.

Relink when:

  • a note explains a low or high component value;
  • a note contradicts the current score interpretation;
  • a note validates a component after further review;
  • governance users need traceability before acting on a recommendation.

Creating Linked Evidence

When creating evidence from this page, include:

  • clear title;
  • evidence excerpt or observation;
  • evidence role;
  • confidence level;
  • source type;
  • enough context for a later reviewer to understand the basis.

Good evidence should make the score more reviewable, not merely repeat the score.

Practical Review Pattern

Use this sequence:

  1. Select the score group.
  2. Inspect the lowest, highest, or most governance-relevant components.
  3. Check whether the component has evidence.
  4. Add or relink evidence where the basis is missing or unclear.
  5. Record review notes for contradictions, uncertainty, or caveats.
  6. Return to Recommendations or Governance Summary only after the important score basis is defensible.

Owner Summary

Score Component Details is a Bridge page. It helps owners trust the movement from Stage A diagnosis to Stage B action by showing whether scores have evidence, whether contradictions are visible, and whether interpretation can be defended before recommendations or governance decisions are made.
