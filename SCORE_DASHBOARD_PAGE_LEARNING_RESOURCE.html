Score Dashboard Page Learning Resource

This guide teaches users how the Score Dashboard computes and explains persisted scorecards.

Purpose

The Score Dashboard converts saved diagnostic and survey inputs into scorecard outputs for the current cycle.

Use it to:

  • compute and persist a scorecard
  • inspect major score fields
  • review confidence labels and contradiction counts
  • inspect execution feedback reassessment
  • review KPI threshold alerts and threshold rules
  • inspect rich integrity-gap explanations
  • review score components by taxonomy
  • export or print persisted scorecard values, score components, and the combined numeric input report

The dashboard is a structured interpretation surface, not final proof of improvement.

Stage A, Stage B, And Bridge Scores

Read the Score Dashboard through three metric roles:

Product roleScore fieldsGovernance meaning
Stage A: Understand realityStructural Health Index, Incentive Integrity, Human Sustainability, Cultural Health, Capability Realism, Technology Alignment, Symbolic Legitimacy, Trust Health, Burnout Risk, AI Capture RiskThese diagnose current workplace conditions.
Stage B: Change reality intelligentlyExecution Feedback Index and KPI or pilot-driven reassessment effectsThese test whether action is producing evidence of movement.
Bridge / governanceOverall Flourishing Score, Integrity Gap, Change Readiness, confidence labels, contradiction countThese connect diagnosis, action readiness, evidence quality, and governance interpretation.

For deeper metric interpretation, use user/metrics/Metrics explained.md and user/metrics/Comprehensive Metric Reference.md.

Compute And Persist Scorecard

Click Compute and Persist Scorecard after diagnostic and survey inputs have been saved.

Persisted scorecards are needed for:

  • Recommendations
  • Comparative Cycle Review
  • Governance Summary
  • board-pack outputs
  • cross-cycle score movement

If inputs change, compute again so downstream pages reflect the current cycle state.

Export And Print

The Export / print saved score data expander appears once Score Dashboard has metric or survey data available for the selected cycle.

Available outputs:

  • Scorecard CSV
  • Score components CSV
  • Printable HTML report combining saved diagnostic inputs, persisted scorecard values, and score components

If no scorecard has been persisted yet, the export section still appears but score export buttons are disabled. The page tells the user to compute and persist a scorecard before downloading score exports.

Exports include persisted records for the current cycle, division, and segment. If the user has just edited Diagnostic Input or Survey Input, they should save those inputs and compute/persist the scorecard again before exporting.

Score Interpretation

Important fields include:

  • Structural Health Index
  • Symbolic Legitimacy Index
  • Integrity Gap
  • Change Readiness
  • Execution Feedback Index
  • Overall Flourishing Score
  • Trust Health
  • Burnout Risk
  • AI Capture Risk

Read the confidence labels and contradiction counts before treating a score as strong.

The Overall Flourishing Score is a bridge score. It combines structural health, symbolic legitimacy, and execution feedback where available, while preserving the rule that symbolic strength cannot compensate for severe structural weakness.

Integrity Gap And Contradictions

The dashboard highlights where alignment-side claims diverge from structural or symbolic realities.

Contradictions requiring re-test should lead to:

  • evidence notes
  • score component review
  • alignment review
  • cautious recommendation interpretation

Downstream Impact

Score Dashboard feeds:

  • Recommendations generation
  • Alignment Dashboard
  • Score Component Details
  • Governance Summary
  • Comparative Cycle Review
  • board-pack exports

The feed matters because Score Dashboard is the point where saved diagnostic and survey inputs become a persisted scorecard. Until a scorecard is computed and persisted, many downstream pages either have no current score basis or are working from an older interpretation. Recomputing after input changes keeps downstream recommendations, explanations, summaries, comparisons, and exports aligned with the current cycle.

Recommendations Generation

Score Dashboard feeds Recommendations generation when the user clicks Compute and Persist Scorecard.

The persisted scorecard can trigger recommendation rules based on:

  • structural health
  • symbolic legitimacy
  • integrity gap
  • change readiness
  • burnout risk
  • trust health
  • AI capture risk
  • contradiction count
  • execution feedback where KPI or pilot outcome evidence exists

The practical downstream impact is that recommendations inherit their initial rationale from the score profile. If the scorecard is stale, generated recommendations may respond to old inputs. If confidence labels are weak or contradictions are present, recommendations should be interpreted cautiously and reviewed against evidence before being accepted or converted into structural decisions.

Recommendations are not automatic truth. They are governed prompts created from the current score interpretation.

Alignment Dashboard

Score Dashboard feeds Alignment Dashboard by surfacing integrity-gap and contradiction signals.

The dashboard highlights:

  • alignment-side values
  • target-side values
  • gap severity
  • contradictions requiring re-test
  • confidence labels
  • linked evidence for alignment components where available

Alignment Dashboard uses this material to help users inspect where symbolic or perceived alignment diverges from structural reality. A large integrity gap can indicate that an organization is claiming or experiencing one thing while its structures support something else.

The downstream impact is contradiction review. Alignment Dashboard should not treat an improved score as enough if alignment gaps or contradiction components remain unresolved. Score Dashboard tells users where the gap appears; Alignment Dashboard helps them review what the gap means and whether evidence supports, qualifies, or contradicts the interpretation.

Score Component Details

Score Dashboard feeds Score Component Details by persisting the component records behind the scorecard.

When a scorecard is persisted, the app stores component-level explanations including:

  • score group
  • component name
  • raw value
  • normalized value
  • weight
  • notes or rationale
  • review status fields

Score Component Details then lets users inspect those components, review linked evidence, relink existing evidence, or create new evidence directly attached to a component.

The practical impact is explainability. Score Dashboard provides the high-level scorecard; Score Component Details explains which component is driving the score and whether that component has enough evidence to support the interpretation. If a top-level score looks surprising, too strong, too weak, or contradicted, Score Component Details is the next review surface.

Governance Summary

Governance Summary uses Score Dashboard outputs as part of the current cycle's executive review.

Score Dashboard can affect Governance Summary through:

  • persisted scorecard values
  • confidence labels
  • contradiction counts
  • score component explanations
  • execution feedback interpretation
  • KPI threshold alerts shown through score reassessment
  • evidence excerpts linked to score components
  • integrity-gap and alignment qualifications

The downstream impact is that Governance Summary can present a cycle-level score profile with qualifications. A strong score with low confidence, unresolved contradictions, or missing component evidence should not be summarized as unqualified progress. A weaker score with strong evidence may be a more reliable governance signal than a stronger score with thin evidence.

Governance Summary depends on the scorecard being current. If diagnostic or survey inputs changed but the scorecard was not recomputed, summary conclusions and board-pack sections may be stale.

Comparative Cycle Review

Comparative Cycle Review uses persisted scorecards to compare the selected cycle against prior cycles.

Score Dashboard affects Comparative Cycle Review through:

  • cross-cycle score movement
  • score coverage and comparable score fields
  • confidence in current and previous scorecards
  • structural, symbolic, alignment, and execution feedback trends
  • contradiction counts and scorecard availability
  • threshold and interpretation stability context when connected to KPI rules

The practical downstream impact is comparative confidence. If a current or previous cycle lacks a persisted scorecard, comparative conclusions are weaker. If the scorecard exists but confidence is low or contradictions are unresolved, cross-cycle improvement should be qualified. If scorecards are current, comparable, and evidence-backed, Comparative Cycle Review can more credibly ask whether governance is improving conditions rather than just producing activity.

Board-Pack Exports

Score Dashboard feeds board-pack exports by supplying the score profile and related qualifications that appear in governance reporting.

Board-pack exports can use Score Dashboard material such as:

  • Structural Health Index
  • Symbolic Legitimacy Index
  • Integrity Gap
  • Execution Feedback Index
  • Overall Flourishing Score
  • trust, burnout, and AI capture risk scores
  • confidence labels
  • contradiction counts
  • score component explanations
  • KPI and pilot-driven execution feedback qualifications

The board-pack impact is significant because exported readers may see only the summarized score narrative. The export should therefore preserve the difference between a score, the confidence behind it, and any contradiction or evidence limitation that qualifies it.

A board pack should not present score movement as proof of improvement by itself. It should explain whether the score is supported by current inputs, whether execution evidence is present, whether contradictions require re-test, and whether downstream recommendations are based on a current persisted scorecard.

Score Dashboard's local printable HTML report is different from a Governance Summary board pack. It is a local record of numeric inputs and score outputs for checking, saving, or printing. It does not replace governance interpretation.

Practical Feed Interpretation

When reviewing downstream impact, use this rule:

Score Dashboard feeds downstream pages with persisted score interpretation, not final proof.

That interpretation can generate recommendations, expose alignment contradictions, create component-level evidence trails, qualify executive summaries, support or weaken cross-cycle comparison, and shape board-pack score narratives. The most important downstream signal is whether the scorecard is current, evidence-aware, and interpreted alongside confidence and contradiction context.

Common Mistakes

Avoid reading an improved score as proof by itself.

Avoid ignoring confidence labels.

Avoid treating missing evidence as support.

Avoid generating recommendations before the scorecard reflects current inputs.

Avoid exporting score data before computing and persisting the current scorecard.

Training Prompt

Ask the trainee to compute a scorecard, identify one strong-looking score and one qualified score, download the scorecard CSV or printable HTML report, then explain which evidence or contradiction should be reviewed next.

Completion standard: the user can interpret the scorecard as a governed signal, not an automatic verdict, and can export the saved score data for local review.
