Governance Execution Review Page Learning Resource

This guide teaches users how the Governance Execution Review page is organized around a selected lineage path and task-specific execution review areas.

The page asks a practical governance question:

> Is a recommendation actually moving through decision, pilot, KPI, scenario pressure, and learning closure, or is execution leaking before conditions change?

Governance Execution Review is not a broad score dashboard. It is the working review surface for lineage-level execution judgement.

In the Stage A / Stage B / Bridge framing, this page is where Stage B execution evidence is reviewed through Bridge governance judgment. It asks whether recommendations, decisions, pilots, KPIs, scenario pressure, evidence, and learning state justify progression, pause, mitigation, reopening, or blockage.

Use it after reading the metric system resources when users need to distinguish a good diagnostic score from a tested execution path.

Purpose

Use Governance Execution Review to answer five execution questions:

  • Decide Progression: Should the selected execution path progress, pause, reopen, require mitigation, require stronger evidence, or be blocked?
  • Diagnose Path Health: Where are execution paths blocked, stalled, mitigation-dependent, weakly evidenced, or leaking between stages?
  • Govern Scenario Pressure: How do linked scenarios, watchpoints, mitigation status, and scenario-to-execution effectiveness affect execution judgement?
  • Close Learning: Which execution outcomes should cause reassessment, revision, scaling, stopping, or reopening?
  • Inspect Selected Path: What is the detailed recommendation, decision, pilot, KPI, and evidence context for the selected lineage path?

The page loads lineage diagnostics for the selected assessment cycle, then asks the user to choose a Selected lineage path. That selected path anchors progression actioning, scenario interpretation, and detailed inspection.

Required Starting Point

The page requires:

  • a selected assessment cycle
  • enough workflow readiness to enter Governance Execution Review
  • lineage rows built from recommendations, structural decisions, pilots, KPIs, and related diagnostics

If no lineage rows are available, the page explains that recommendations can exist before execution lineage exists. A recommendation may need conversion into structural decisions and linkage to pilots or KPIs before this page has a path to inspect.

Selected Lineage Path

The Selected lineage path selector combines:

  • recommendation title
  • structural decision element
  • pilot title
  • path identifier

This selection matters. Several areas use the selected path as the anchor for row-level reading, governed action, scenario context, KPI context, and evidence re-linking.

Before applying any action, inspect the selected path's:

  • path state
  • review state
  • governance context
  • recommendation
  • decision
  • pilot
  • semantic classification
  • routing or handling cue
  • reasons
  • weak execution signals
  • evidence gap reasons

Execution Review Area Buttons

The Execution review area selector contains:

  • Decide Progression
  • Diagnose Path Health
  • Govern Scenario Pressure
  • Close Learning
  • Inspect Selected Path

Each area serves a different task.

Decide Progression

Use Decide Progression when the governance question is what should happen next to the selected execution path.

This area shows:

  • selected path decision context
  • selected-row governance reading
  • progression-relevant entity status
  • escalation-to-action coupling
  • governed action controls

The selected path decision context shows path state, review state, governance context, recommendation, decision, and pilot.

The selected-row governance reading shows review context, semantic caption, handling caption, reasons, weak execution reasons, and evidence gap reasons. Read these before choosing an action.

Progression-relevant entity status shows current recommendation lifecycle, structural decision status, and pilot status when those entities can be resolved.

Available governed actions are:

  • approve progression
  • require mitigation first
  • require evidence strengthening
  • reopen for revision
  • block progression

The main action is Apply governed action. Applying a governed action calls the governance execution service, clears cached page context for the cycle, records allowed status changes, and reloads the page. If current rules do not allow a status change, the page says no status change was allowed.

Do not treat the action selector as automatic authority. It is a controlled workflow action that should follow the row's evidence, scenario pressure, KPI context, and routing meaning.

Diagnose Path Health

Use Diagnose Path Health when the governance question is where execution is leaking across the cycle.

This area shows:

  • comparative execution leakage
  • stage-by-stage conversion table
  • conversion-rate chart
  • weak execution path count
  • evidence gap count
  • blocked path count
  • stalled path count
  • execution-path diagnostics
  • execution health by domain
  • execution path-state summary
  • blocked execution paths
  • stalled execution paths
  • mitigation-dependent execution paths

Execution-path diagnostics include recommendation, decision, pilot, path state, review state, governance context, current classification, governance handling, key reasons, weak execution signals, evidence gaps, and recommended next step.

Use this area to find structural patterns. A single selected path may look manageable, but domain health and drop-off tables can show whether execution weakness is isolated or systemic.

Blocked, stalled, and mitigation-dependent sections should be read as governance triage. They identify where work may need stronger evidence, scenario mitigation, revision, or progression blockage.

Govern Scenario Pressure

Use Govern Scenario Pressure when scenario pressure may qualify execution judgement.

This area shows:

  • scenario-to-execution effectiveness
  • scenario response effectiveness chart
  • scenario execution review context
  • linked scenario and mitigation context for the selected path

Scenario-to-execution effectiveness shows whether scenario-linked work has meaningful execution support, mitigation, linked recommendations, linked decisions, pilots, KPIs, weak execution flags, and review prompts.

Scenario execution review context shows scenario, entity, review state, governance context, current classification, governance handling, and recommended next step.

Linked scenario and mitigation context uses the selected path's linked scenario ID. If no linked scenario alerts exist for the selected row, the page says so.

Scenario pressure should not be read as a general reason to stop or approve work. It qualifies the selected path. Use it to decide whether mitigation must happen first, whether evidence is too weak, or whether progression can continue under current conditions.

Close Learning

Use Close Learning when execution outcomes should be converted into learning interpretation.

This area shows:

  • validated pilot count
  • contradicted pilot count
  • KPI reassessment trigger count
  • reopen candidate count
  • execution evidence and KPI outcome warning when data is unavailable
  • reopen candidate rows

Close Learning does not redesign the learning-closure service. It displays where execution evidence should cause reassessment, revision, scaling, stopping, or reopening.

Reopen candidate rows include entity type, entity ID, title, reason, severity, and recommended action. Severity is derived from learning state: contradicted items are high, inconclusive items are medium, and other candidates are lower priority.

If there is no execution evidence or KPI outcome data, complete pilot tracking and KPI capture before relying on learning closure.

Inspect Selected Path

Use Inspect Selected Path for detailed traceability and evidence repair.

This area shows:

  • selected path decision context
  • selected-row governance reading
  • current workflow entities
  • KPI context
  • evidence re-linking for the selected execution path
  • currently linked evidence

Current workflow entities can show:

  • recommendation execution summary, including scenario state, domain mitigation, and counts of decisions, pilots, and KPIs
  • structural decision rule status
  • pilot status, alert count, critical unmitigated alert count, and average KPI progress
  • linked KPI rows, including progress score, status, and evaluated governance state

Evidence re-linking attaches an existing evidence note to the selected recommendation, structural decision, pilot, and optionally a KPI. It does not create a new evidence note.

The main evidence action is Save evidence re-link for this execution path. Saving re-links the evidence, updates audit history, clears cached context, and reloads the page.

If no evidence is linked to the selected path, the page warns that this is an evidence traceability gap. Create new evidence in Evidence Notes first, then return here to re-link it.

Semantic, Context, And Routing Lines

Selected lineage rows can show:

  • governance context
  • semantic caption
  • handling or routing caption
  • reasons
  • weak execution reasons
  • evidence gap reasons

Use these cues to distinguish:

  • progressing paths
  • weak execution paths
  • evidence gaps
  • stalled paths
  • blocked paths
  • mitigation-dependent paths
  • caution prompts
  • reassessment needs
  • redesign-oriented concerns

Semantic and routing cues guide bounded governance review. They do not replace human judgement, and they do not create automatic decision authority.

Downstream Impact

Governance Execution Review feeds downstream interpretation by clarifying whether execution is actually moving through the workflow.

It connects to:

  • Governance Summary, through lineage diagnostics, scenario effectiveness, execution leakage, and board-pack qualifications
  • Governance Action Queue, when learning-driven or governed follow-up work becomes ownerable elsewhere
  • Governance Action Review and Review History, through governed actions and evidence re-link audit records
  • Foresight Execution, through scenario watchpoints and mitigation context
  • Evidence Notes, through existing evidence that may need creation before re-linking
  • Lineage View, through recommendation-to-decision-to-pilot-to-KPI traceability
  • KPI Dashboard and Pilot Tracker, through outcome data needed for learning closure

The page should help users decide whether an execution path can progress, must pause, needs mitigation, needs stronger evidence, should reopen, or should be blocked.

Common Mistakes

Avoid applying governed actions before reading selected-row reasons and routing cues.

Avoid approving progression when evidence is insufficient, KPI context is absent, or contradiction is unresolved.

Avoid treating scenario watchpoints as mitigated merely because they are visible.

Avoid treating scenario mitigation as effective without linked decision, pilot, KPI, or evidence support.

Avoid using evidence re-linking as if it creates new evidence.

Avoid interpreting a single selected path without also checking Diagnose Path Health for cycle-level leakage patterns.

Avoid reading semantic routing as automatic authority. It guides bounded review.

Best-Practice Review Pattern

  1. Select the intended assessment cycle.
  2. Choose the relevant Selected lineage path.
  3. Open Decide Progression to read the selected row and decide whether action is needed.
  4. Open Diagnose Path Health to see whether the selected issue is part of a wider execution pattern.
  5. Open Govern Scenario Pressure when scenario or mitigation context may qualify the path.
  6. Open Inspect Selected Path to review recommendation, decision, pilot, KPI, and evidence details.
  7. Re-link existing evidence only when the evidence note already belongs to the selected execution path.
  8. Open Close Learning to see whether execution outcomes should trigger reassessment, revision, scaling, stopping, or reopening.
  9. Apply governed action only when the evidence, scenario, KPI, learning, and routing context support it.

Training Prompt

Ask the trainee to select one lineage path, read its path state, governance context, semantic caption, routing cue, weak execution signals, and evidence gaps. Then ask whether the path should progress, require mitigation first, require evidence strengthening, reopen for revision, block progression, or remain under monitoring.

Completion standard: the user can explain why a selected execution path should progress, pause, strengthen evidence, reopen, or block based on the revised area arrangement.
