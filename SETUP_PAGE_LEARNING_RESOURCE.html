Setup Page Learning Resource

This guide teaches users how the **Setup** page works and why organization and attribution context matter before any governance interpretation begins.

Purpose

The Setup page creates and selects the organization workspace and the users who will be used for attribution.

Use it to:

  • create a new organization
  • select an existing organization
  • inspect stored organization fields
  • edit organization details
  • create or edit attribution users
  • select the active attribution user

The page establishes the workspace boundary. Most later records belong to the selected organization.

Organization Workspace

An organization is the main container for cycles, users, metrics, evidence, recommendations, decisions, pilots, KPIs, scenarios, and review history.

Create a new organization only when the workplace or training example is genuinely new. Existing names are blocked to protect continuity.

Select an existing organization when continuing prior work.

Sample data, when loaded from Home, is stored under the sample organization **Southern Horizon Health Services** and marked as sample data. A real organization created in Setup is separate from that sample workspace.

Attribution Users

Attribution users record who is acting in the system. They are used by evidence notes, review history, governance actions, continuity corrections, and learning workflows.

Common roles include:

  • analyst
  • transformation lead
  • executive sponsor
  • reviewer

The active attribution user is not just a display setting. It helps later reviewers understand who created or changed records.

What The User Should Notice

Ask the user to identify:

  • selected organization
  • whether the selected organization is sample data or user data
  • sector and geography
  • active attribution user
  • role
  • local database path
  • persisted organizations list

If no organization is selected, most downstream pages cannot behave meaningfully.

Downstream Impact

Setup affects:

  • Assessment Cycle: cycles are attached to the selected organization.
  • Evidence Notes: evidence is attributed to a user.
  • Recommendations and decisions: ownership and history are organization-scoped.
  • Review History: actor names make changes auditable.
  • Sidebar filters: division and segment options depend on organization context.

Common Mistakes

Avoid creating duplicate organizations for the same workplace.

Avoid entering real evidence into the sample organization.

Avoid entering evidence before selecting the correct attribution user.

Avoid treating a user role as a permission model. It is primarily attribution and review context unless a workflow explicitly uses it.

Training Prompt

Ask the trainee to create or select an organization, create or select an attribution user, and then explain how those selections will affect evidence and review history.

Completion standard: the user can explain the selected workspace and actor before entering data.
