Preserve / Reform / Replace Page Learning Resource

This guide teaches users how the Preserve / Reform / Replace page turns accepted recommendations into governed structural decisions.

Purpose

The page is the structural decision matrix. It asks whether a structural element should be preserved, reformed, replaced, or watched.

Use it to:

  • create structural decision items
  • link decisions to recommendations, scenarios, and evidence
  • update decision workflow status
  • review mitigation-aware domain state
  • apply decision learning actions
  • create or link pilots for selected decisions

This page moves the app from recommendation to governed choice.

Stage A To Stage B Decision Role

Preserve / Reform / Replace is where Stage A diagnosis becomes a governed structural choice. The decision category should be grounded in diagnostic evidence, score interpretation, integrity-gap review, scenario context, and evidence confidence.

Use the metric framing this way:

  • Stage A metrics explain what condition or structure is at issue.
  • Bridge signals, such as integrity gap, scenario pressure, confidence, and evidence linkage, qualify whether the decision is ready.
  • Stage B signals, such as pilot and KPI evidence, later test whether the decision worked.

Decision Categories

Use:

  • preserve when a structure is working and should be protected
  • reform when the structure needs adjustment
  • replace when the structure is materially wrong or harmful
  • watch when more evidence is needed before deciding

The category should match evidence and governance context, not preference.

Workflow Status

Typical workflow statuses include:

  • draft
  • review
  • accepted
  • pilot_planned
  • implemented

The page checks workflow rules and scenario pressure before allowing some updates.

Scenario And Mitigation Context

A decision can be linked to a scenario. Scenario escalation and mitigation-aware domain state help prevent users from advancing decisions while unmitigated or critical pressure remains unresolved.

Read:

  • scenario escalation
  • mitigation-aware domain state
  • alert count
  • unmitigated count
  • critical count

Learning Actions

Decision learning state is separate from workflow status.

Use learning actions when evidence shows the decision is being tested, validated, contradicted, or superseded.

Review History records workflow and learning changes.

Downstream Impact

Preserve / Reform / Replace feeds:

  • Pilot Tracker
  • KPI Dashboard
  • Lineage View
  • Governance Execution Review
  • Governance Summary
  • Review History
  • board-pack output

Common Mistakes

Avoid converting every recommendation into a decision too early.

Avoid accepting a decision while critical unmitigated scenario pressure remains unresolved.

Avoid confusing accepted with validated.

Avoid creating pilots without a clear decision hypothesis.

Training Prompt

Ask the trainee to convert or create one decision, classify it as preserve/reform/replace/watch, review scenario pressure, and explain whether it is ready for a pilot.

Completion standard: the user can explain why a recommendation became a structural decision and what evidence qualifies it.
